# CANSLIM 스타일 성장주 스크리너

`yfinance`를 사용하는 **CANSLIM 초기 후보군** 스크리닝용 단일 스크립트(`canslim_template.py`) 프로젝트입니다. 재무·가격 데이터를 조합해 규칙 통과 여부와 간단한 점수를 산출합니다.

## 개요

| 항목 | 설명 |
|------|------|
| 데이터 소스 | Yahoo Finance (`yfinance`) — 무료·편리하나 기관급 정합성은 아님 |
| 출력 | `canslim_screen_results.csv` (실행 시 덮어씀) |
| 벤치마크 | 기본 `^IXIC`(나스닥 종합), 한국은 `^KS11` 등으로 변경 가능 |

### 스크리닝에 포함되는 지표

스크립트 상단의 미국·한국 티커 예시(`TICKERS_US`, `TICKERS_KR_EXAMPLE`)를 바꿔 유니버스를 구성할 수 있습니다.

- 최근 분기 매출 전년동기대비(YoY)
- 연간 매출 성장률(직전 연도 대비)
- 52주 신고가 대비 현재가 괴리(`pct_from_52w_high`)
- 50일 평균 달러 거래대금(`Close × Volume`)
- 벤치마크 대비 약 6개월(126거래일) 상대강도
- 시가총액 상한 필터(스크립트 내 `max_market_cap_usd`)
- 규칙별 통과 여부, 룰 통과 수(`passed_rules`), 점수(`score`)

## 요구 사항

- Python 3.9+ 권장  
- 패키지: `yfinance`, `pandas`, `numpy`

```bash
python -m venv .venv
.venv\Scripts\activate
pip install yfinance pandas numpy
```

가상환경 없이 빠르게 쓸 때는 다음만으로도 동작합니다.

```bash
pip install yfinance pandas numpy
```

> **권장:** 재현 가능한 환경을 위해 `requirements.txt`에 버전을 고정하는 편이 좋습니다. (현재 저장소에는 없음 — [개선 제안](#소스-검토--개선-제안) 참고)

## 실행

```bash
python canslim_template.py
```

콘솔에는 `passed_rules`가 높은 종목 위주로 요약이 출력되고, 전체 결과는 `canslim_screen_results.csv`에 저장됩니다.

## 주요 설정 (`canslim_template.py`)

| 변수 / 블록 | 역할 |
|-------------|------|
| `USE_TICKERS` | 스크리닝 대상 유니버스 (`TICKERS_US` / `TICKERS_KR_EXAMPLE` 등) |
| `BENCHMARK` | 상대강도 계산용 지수 티커 |
| `RULES` | 성장·52주 고가 근접·유동성·RS·시총 등 임계값 |
| `compute_financial_metrics()` | EPS, 영업이익, 기관 수급 등 추가 시 확장 지점 |

한국 종목은 Yahoo 티커 접미사(`.KS`, `.KQ` 등)를 데이터 제공 환경에 맞게 확인해야 합니다.

**커스터마이징 요약:** `USE_TICKERS`(유니버스), `BENCHMARK`(미국 예: `^IXIC`, 한국 예: `^KS11`), `RULES`(임계값), `compute_financial_metrics()`(EPS·영업이익·기관 수급 등 확장)를 조정하면 됩니다.

## 주의 (데이터 한계·실전 보강)

- `yfinance` 데이터는 무료·비공식에 가깝고, 누락이나 재무 필드 명칭 불일치가 있을 수 있습니다.
- 한국 종목은 Yahoo 티커 접미사(`.KS`, `.KQ` 등)를 반드시 조회 결과로 확인하세요.
- 실거래·리서치용이라면 [Finnhub](https://finnhub.io/), [Polygon](https://polygon.io/), [Alpha Vantage](https://www.alphavantage.co/), 증권사 API 등으로 교차 검증·보강하는 것이 좋습니다.

## 소스 검토 · 개선 제안

아래는 `canslim_template.py` 기준 코드 리뷰 요약입니다. 우선순위는 프로젝트 목적(학습용 / 운영용)에 맞게 조정하면 됩니다.

### 구조·운영

1. **`requirements.txt` 부재** — 의존성 버전이 고정되어 있지 않아 환경마다 결과·동작이 달라질 수 있습니다. `pip freeze` 또는 합리적인 하한 버전을 명시하는 것을 권장합니다.
2. **CLI 인자 없음** — 출력 CSV 경로, 티커 목록, 벤치마크 등이 코드 수정 없이는 바뀌지 않습니다. `argparse` 또는 환경 변수로 분리하면 재사용성이 좋아집니다.
3. **순차 API 호출** — 티커마다 `download`/`Ticker`를 호출합니다. 대량 유니버스에서는 비공식 rate limit에 걸릴 수 있어, 요청 간 지연·배치·캐시 전략을 검토할 가치가 있습니다.

### 데이터·로직 정확도

4. **`LOOKBACK_DAYS` 미사용** — 상단에 `LOOKBACK_DAYS = 260`이 있으나, 52주 고가는 `tail(252)` 등으로만 계산됩니다. 의도한 룩백과 코드가 일치하지 않으므로 상수를 실제 계산에 반영하거나 제거하는 편이 명확합니다.
5. **분기 YoY 매출** — `vals.iloc[-1]`과 `vals.iloc[-5]` 비교는 열이 시계열상 정확히 4분기 간격이라는 가정에 의존합니다. 결산월·누락 분기가 있으면 왜곡될 수 있습니다.
6. **연간 매출 성장** — 마지막 두 연도만 비교합니다. 다년 CAGR 등으로 바꾸면 CANSLIM의 “지속 성장” 해석에 더 가깝게 튜닝할 수 있습니다.
7. **상대강도 정렬** — 벤치마크와 종목의 영업일을 `inner` 조인합니다. 휴장일 불일치 시 샘플 길이가 줄어들 수 있어, 필요하면 리샘플링/전방 채움 등 정책을 문서화하는 것이 좋습니다.
8. **시총 규칙 명명** — `max_market_cap_usd` 이하만 통과(`size_ok`)이므로 “대형주 제외”에 가깝습니다. 주석의 “early-stage bias”와 코드 의미가 항상 일치하는지, 팀 내에서 용어를 통일하는 것이 좋습니다.

### 견고성·관측 가능성

9. **전역 `warnings.filterwarnings("ignore")`** — 모든 경고를 숨겨 디버깅이 어려워질 수 있습니다. 특정 카테고리만 끄거나, 외부 라이브러리 구간만 좁게 무시하는 편이 안전합니다.
10. **광범위한 `except`** — 재무 블록에서 예외를 삼키면 원인 파악이 어렵습니다. 로깅(`logging`)이나 “한 번만 verbose” 모드에서 스택/티커를 남기는 방식을 고려할 수 있습니다.
11. **`yf.download` 반환 형식** — 멀티 인덱스 컬럼 처리는 단순화되어 있어, 티커/버전에 따라 열 구조가 달라지면 깨질 여지가 있습니다. 실패 시 재시도·검증 로직이 있으면 좋습니다.

### 제품·리스크 고지

12. **투자 판단용 아님** — 무료 데이터 지연·누락·재무 필드 명칭 변경 가능성이 있습니다. 실전용이면 증권사·Polygon·Finnhub·Alpha Vantage 등 유료/공식 채널과의 교차 검증이 필요합니다.
13. **통화 혼합** — 한국 현지 주식의 거래대금·가격 표시 통화는 티커/시장에 따라 다를 수 있습니다. 단일 “USD” 기준 규칙을 적용하기 전에 데이터 정의를 확인해야 합니다.

### 테스트·품질

14. **단위 테스트 부재** — `pct_change`, `safe_get`, `pass_rules` 등은 순수 로직에 가깝습니다. 고정된 작은 DataFrame으로 스냅샷 테스트를 두면 리팩터링 시 안전합니다.
